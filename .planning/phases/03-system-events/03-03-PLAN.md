    **`Sources/PicCore/System/DisplayWatcher.swift`（新建）** —— 一个类型带两个 reason。理由写进文件头：`CGDisplayIsAsleep` 与 `willSleep/didWake` 都属显示/电源域、共享同一条重算路径，拆成两个类型只会让「唤醒后立刻重算」这条规则写两遍。

    ```swift
    public struct DisplaySignals: Equatable, Sendable {
        public var displayAsleep: Bool      // → HoldReason.displayAsleep
        public var systemSleeping: Bool     // → HoldReason.systemSleeping
    }

    @MainActor public final class DisplayWatcher {
        public init(notificationCenter: NotificationCenter = .default())
        /// 返回两个 reason 各自是否生效；接线时拆成两次 arbiter.set(_:active:)
        public func start(onChange: @escaping (DisplaySignals) -> Void)
        public func stop()
        public func currentSignals() -> DisplaySignals
    }
    ```

    - **两个 reason 各自独立**：`start` 的 `onChange` 传 `DisplaySignals` 两个字段，接线方（03-05）拆成两次 `arbiter.set`。`DisplayWatcher` 内部**不许**出现 `HoldArbiter` —— 它只产出信号（D-09）。
    - `displayAsleep` 的当前值 = `CGDisplayIsAsleep(CGMainDisplayID()) != 0`。
    - `systemSleeping` **不从任何轮询读** —— `willSleepNotification` 置位、`didWakeNotification` 清除，且这两个通知是唯一切换它的入口。内存里一个 `Bool` 字段，记在文件头注明「这是唯一允许的状态字段，它由两个通知对驱动，不来自任何采样」。
    - **重算路径唯一**：私有 `re-evaluate()` 是唯一读值并回调的地方，由三个入口调 —— ① `CGDisplayRegisterReconfigurationCallback` 注册的回调；② `willSleepNotification`（置位后立即重算）；③ `didWakeNotification`（清除后立即重算）。**不得**在回调里直接写 `onChange`，必须过 `re-evaluate()`，否则唤醒路径与暂停路径会不对称（Pitfall 7）。
    - 三个 token / 回调句柄都要能被 `stop()` 释放：`NSWorkspace` 的两个观察者 token 存数组；`CGDisplayRegisterReconfigurationCallback` 的回调在 `stop()` 里用 `CGDisplayRemoveReconfigurationCallback` 摘掉。**摘不掉就是永久泄漏**（文件头点名 Pitfall 4）。
    - 允许 `import Foundation` + `import CoreGraphics`。**不允许** `import AVFoundation`，不允许出现 `player` / `AVPlayer`。`NSWorkspace` 的两个通知名要作为常量暴露（`DisplayWatcher.sleepNotificationName` / `.wakeNotificationName`），供 03-05 接线与探针打印确切名字。
