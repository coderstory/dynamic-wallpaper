## 3. 配色令牌（B1 深海）

**深色为主设计。** 浅色变体**未设计**（见 §9 待定项）。

```swift
// 背景与文字
bg          #0A1826   窗口底
fg          #DCE8F4   主文字
fgMuted     rgba(220,232,244,0.60)
sep         rgba(90,170,240,0.16)   分隔线
card        rgba(13,32,52,0.92)      卡片底

// 强调
accent      #4CC4F5   天蓝 —— 唯一强调色
accentFg    #04202E   accent 上的文字
glow        rgba(76,196,245,0.32)    发光
edge        rgba(90,190,255,0.32)    描边

// 警告（空态专用）
warn        #F5B544
warnGlow    rgba(245,181,68,0.30)
```

**窗口环境光**：顶部 `LinearGradient` 从 `rgba(76,196,245,0.14)` 渐隐到 40% 处；右下角一枚 `RadialGradient` 补光。整体 10 秒呼吸（opacity 0.5 ↔ 1.0）。**必须尊重 `prefers-reduced-motion`，关掉动画。**

**颗粒**：一层低透明度噪点叠加，`mix-blend-mode: overlay`。可选，视觉上让深色不显得平。

## 4. 布局（L4 双列紧跟）

```
┌──────────────────────────────────────────────────────────────┐
│ ●●●                Pic 设置                                   │
├───────────────────────────────┬──────────────────────────────┤
│ 壁纸来源                       │ 电源与系统                    │
│ ┌───────────────────────────┐ │ ┌──────────────────────────┐ │
│ │ 📁 文件夹  ~/Movies/… [选择…]│ │ │ 🔋 电池时播放      [关]  │ │
│ │ ● 12 个可用视频   [重新扫描] │ │ │ ⏻ 开机自启         [关]  │ │
│ └───────────────────────────┘ │ └──────────────────────────┘ │
│ 递归扫子目录 · 只认 MP4/MOV/M4V │ 全屏/锁屏/熄屏/睡眠时自动暂停  │
│                               │                              │
│ 播放                           │ 维护                          │
│ ┌───────────────────────────┐ │ ┌──────────────────────────┐ │
│ │ ◐ 模式  (单|列表循环|随机)  │ │ │ ↻ 重新扫描        [扫描] │ │
│ │ ◷ 轮换  ▼ 15 分钟 ▲       │ │ │ ⇄ 转码 MKV/AVI→MP4 [打开…]│ │
│ │ » 速度  ──●──  1.00×      │ │ └──────────────────────────┘ │
│ │ ♪ 声音  ──●── 60%  [●]    │ │                              │
│ └───────────────────────────┘ │                              │
└───────────────────────────────┴──────────────────────────────┘
```

**核心规则 —— 控件紧跟标签右端，`margin-left: auto` 但整行不拉满。** 行内是 `flex`，标签组在左、控件组紧随，两者之间固定 12pt 间隙。

> 与 macOS 系统设置的区别：系统设置是标签右对齐成槽、控件左对齐；**本设计是标签左对齐、控件紧跟其后**。这是用户在 L1–L4 里明确选 L4 的结果。

## 5. 控件清单

每行统一结构：**彩色图标瓷砖（26×26，圆角 6）+ 标签 + 副标签 + 控件**。

| 行 | 图标 | 标签 | 控件 | 类型 |
|---|---|---|---|---|
| 来源 | 📁 蓝 | 文件夹 + 路径 | `选择…` | 按钮 → `NSOpenPanel` |
| 来源 | ● 圆点/感叹号 | **N 个可用视频** | `重新扫描` | 计数 + 按钮 |
| 播放 | ◐ | 模式 | 单循环 / 列表循环 / 随机 | 分段控件 |
| 播放 | ◷ | 轮换 + 副标签 | ▼ 15 分钟 ▲ | 步进器 |
| 播放 | » | 速度 + 「音高不变」 | 滑杆 + `1.00×` | 滑杆 |
| 播放 | ♪ | 声音 | 滑杆 + `60%` + 开关 | 滑杆 + 开关 |
| 电源 | 🔋 | 电池时播放 + 「默认关」 | 开关 | 开关 |
| 电源 | ⏻ | 开机自启 | 开关 | 开关 |
| 维护 | ↻ | 重新扫描 | `扫描` | 按钮 |
| 维护 | ⇄ | 转码 + 「MKV/AVI → MP4」 | `打开…` | 主按钮 → 独立窗口 |

**图标瓷砖**：`LinearGradient(160deg, #5AC8FA → #1668B8)`，描边 `edge`，外发光 `glow`。空态用警告配色 `#F7C463 → #C47A10`。

**滑杆**：`accent-color` = accent。数值**写进右侧标签**，滑杆本身看不出是 0.5 还是 1.5。

## 6. 状态

### 正常态
计数：**蓝色发光大数字（20pt）** + 呼吸圆点 + 「个可用视频」。副行显示扫描规则和上次扫描时间。

### 空态（扫到 0 个）— 必须有
- 数字转**警告黄** `#F5B544`，发光换成 `warnGlow`
- 圆点换成**感叹号图标**，瓷砖换警告配色
- 副行文案：**「没找到能播的文件。壁纸已隐藏，桌面显示的是系统原壁纸。」**

> 这行文案是硬需求 —— 「没有可播视频就露出系统壁纸」是产品决策，界面必须说清楚，否则用户会盯着没动静的桌面猜。

### 置灰联动（两条）
1. 播放模式 =「单循环」→ **轮换时间整行置灰**
2. 声音开关 = 关 → **音量滑杆置灰**

置灰用 `opacity: 0.34`，并**禁用交互**（不是只调透明度）。选置灰而不是隐藏 —— 隐藏会让人怀疑自己记错了。

**全 app 唯一出现列表的地方** —— 这是任务队列，不是给用户浏览壁纸库的。此例外需写进 Phase 计划，否则会被当 scope creep 砍掉。

## 9. 实现约束（已编译/SDK 验证，别再踩）

| 事实 | 影响 |
|---|---|
| **SwiftUI 没有 `SliderStyle`** | 27 个 `*Style` 协议里没有它。滑杆无法完全换肤，`.tint()` 只能改填充色。要完全控制需 `DragGesture` 自绘（约 40 行） |
| `ToggleStyle` 存在 | 开关可完全自定义（含发光），已编译通过 |
| `PickerStyle` 存在 | 分段控件可用 `.tint()` |
| `.shadow(color:radius:)` 可叠 | 双层 = 发光效果 |
| `.ultraThinMaterial` + `NSVisualEffectView` 可用 | 玻璃效果 |
| **发光 = 阴影 + 模糊，吃 GPU** | 设置窗偶尔开一次无妨，**不要做成常驻动画** |
| `AVPlayerItem` 没有 `rate` | 速度在 `AVPlayer` 上 |
| `AVPlayerLooper` 副本初始化时冻结 | 改模板 item 属性不生效 → **音量/速度必须挂 `AVPlayer`**，否则「改设置立即生效」是假的 |
| `NSWindow` 没有 `isIgnoringMouseEvents` | 在 `NSView.ignoresMouseEvents` |

## 9.5 已定（2026-10-03 补充）

| 项 | 决定 | 理由 |
|---|---|---|
| **字体** | **打包 IBM Plex Mono 进 app** | 设计里的「仪器感」全靠等宽字撑。OFL 许可可自由分发，代价约几百 KB。备选是系统 SF Mono，但字形不同，观感会变 |
| **滑杆** | **`DragGesture` 自绘** | 没有 `SliderStyle`，系统滑杆外观与本设计不搭。约 40 行 |
| **分段控件** | 先用 `.tint()` 试；不可接受则自绘 | `.tint()` 对 macOS 分段控件的着色范围有限，需 spike 实测 |

## 11. 已落地的 SwiftUI Spike（2026-10-03）

**`.planning/spike/SettingsSpike.swift` —— 可编译、可渲染，不是纸面设计。**

编译验证：`swiftc -parse-as-library -target arm64-apple-macosx15.0` 通过，用 `ImageRenderer` 渲染成 PNG。
截图：`.planning/design/shots/spike-v3.png`（v1 为修复前，用于对比）

### 实测确认可行的
自绘分段控件 · 自绘滑杆（`DragGesture`）· 自定义 `ToggleStyle`（含发光）· 图标瓷砖双阴影发光 · 呼吸渐变背景 · 等宽字体标签 · 卡片描边

### 踩到并修掉的 2 个真坑
1. **`Card` 上的 `.clipShape(RoundedRectangle)` 会把内部图标砖的外发光裁掉** —— 发光在卡片边缘处直接消失。去掉 `clipShape`，改用 `background` + `overlay` 描边。
2. **写死窗口高度会留一截空白** —— 改用 `.fixedSize(horizontal: false, vertical: true)` 让高度按内容撑，780×388 正好。

### 与新需求：运行状态卡
Spike 里在右列加了「运行状态」卡（已暂停 + 原因 / ffmpeg 状态）。理由：暂停逻辑是 **veto set 仲裁**（见 PAUSE-07），多个条件叠加时用户需要知道**当前到底卡在哪个原因上**，否则会误判成 bug。这一条应补进 REQUIREMENTS。

### 仍与 HTML 稿有差的地方（已知，非缺陷）
| 差异 | 状态 |
|---|---|
| 字体是 SF Mono，非 IBM Plex Mono | 待打包字体（UI-SPEC §9.5 已定用 IBM Plex Mono） |
| 图标用 SF Symbols，非手绘 SVG | 形状不同但风格一致，可接受；若要 100% 一致需自绘 |
| 分段控件比 HTML 略窄 | 微调即可 |
| 无窗口标题栏 | `ImageRenderer` 只渲内容视图，真实 app 有红绿灯标题栏 |

## 12. 图标（2026-10-03 定稿）

### 设计
**概念 C「桌面层」** —— 一块窗压在另一块窗上，前面那块里嵌播放三角。几何按 512 轴严格对齐。

### 配色
**暖白 + 橙**（与设置窗的深海蓝**不同源**，是刻意的：图标要在壁纸上跳出来，界面要压得住）

| 元素 | 值 |
|---|---|
| 背景 | `#FFF9F2 → #F7E9D8` 线性渐变 |
| 光晕 | `#FFA43D` 径向，中心 (50%, 52%)，42% → 0% |
| 前窗 | `#FFAE4D → #E8641A` 线性渐变 |
| 后窗 | `#F08A2E` 描边，30px，42% 不透明 |
| 三角 | 纯白，**R3 最圆**（描边 78 → 圆角半径 39） |
| 基线 | `#E8641A` 描边，34px，30% 不透明 |

### 几何（全部按 512 轴对齐，已实测校验）
| 元素 | 坐标 | 中心 |
|---|---|---|
| 前窗 | x=212 w=600, y=368 h=330 | 512 |
| 后窗 | x=252 w=520, y=250 h=280 | 512 |
| 三角 | x=448 w=128, y=469 h=128 | 512（视觉补偿另加） |
| 基线 | x=300 w=424, y=770 | 512 |
| 整体纵向 | y 250..770 | 510 ≈ 512 |

### 已踩的坑
1. **`drawLinearGradient` 默认不填充起止点以外的区域** —— 表现为圆角方图标右下角被斜切。必须传 `[.drawsBeforeStartLocation, .drawsAfterEndLocation]`。
2. **菜单栏模板图不能用实心填充** —— 模板图是遮罩，前窗实心 + 三角实心 = 一整块黑。**必须靠透明间隙成形**：窗框描边，只有三角实心。

### 产出
- **App 图标**：`.planning/design/assets/` 下 10 个 PNG（16→1024 全套）+ `Contents.json`，可直接当 `AppIcon.appiconset` 用
- **菜单栏图标（已定稿）**：`menubar-v1*.png`（@1x/@2x/@3x）—— **单窗 + 三角**
  - `menubar-v2*.png`（双窗 + 三角）**不采用**，保留在设计目录作对照，**不进 app bundle**
- **生成器**：`tools/make-icons.swift`，可重跑
- **检查图**：`.planning/design/shots/icons-app.png` / `icons-menubar.png`

### 定稿（2026-10-03）

**菜单栏图标 = v1（单窗 + 三角）。** 用户拍板。

理由：模板图只有 22pt 高，v2 的双窗描边在 @1x 下两根窗框线会挤在 4–5 像素里，辨识度不如 v1 的开阔单窗。v1 与 app 图标不同源是可接受的代价 —— 菜单栏要的是**一眼认得出**，不是**和图标长得像**。

**打包时的落地要求（Phase 5 / Phase 7）：**
- app bundle 内只放 v1 的 `@1x/@2x/@3x` 三张，命名 `MenuBarIcon.png` / `@2x` / `@3x`
- 必须设 `isTemplate = true`（`NSImage`），否则深色菜单栏下是黑块
- app 图标走 `.planning/design/assets/` 的 10 张 PNG + `Contents.json`（`AppIcon.appiconset` 格式），由 `build.sh` 里的 `actool` 编成 `.icns` 或直接放进 bundle
