## v1.2 — 用户指出「四个布局是一样的，只是换了颜色」，确认属实并重做

**用户是对的。** 上一版四个方向共用同一套 DOM 与版式，差异只在令牌层（色 / 圆角 / 字体 / 描边）。
那是**四套主题，不是四个方向**。我把「组件级差异」说成了「方向差异」，属过度声称。

**重做：四个方向 = 四种布局模型**

| | 布局模型 | 导航 | 控件位置 |
|---|---|---|---|
| A 精密仪表 | 单栏行式 | 顶部胶囊标签 | 与标签同行 · 右端对齐成竖线 |
| B 编辑杂志 | 段落长卷（无卡片） | 页首文字目录，**无标签栏** | 在标签**下方** · 左对齐 |
| C 暗房终端 | 双栏 148px 索引 + 参数表 | **左侧编号索引** | 键值表内嵌（键 ··· 值） |
| D 圆润亲和 | 2 列磁贴网格 | 顶部胶囊标签 | **满宽**占据磁贴主体 |

- explorer 现在每个方向都渲染：播放页 + **片库页** + 菜单面板，明暗各一
- 补片库页的理由：队列是全 app 唯一的列表，布局模型能不能扛住列表才是选型关键

**发现并修掉的真实缺陷**

`--surface` 在浅色主题下比 `--surface-2` 亮，在深色主题下比 `--surface-2` 暗——**语义是反的**。
用在 C 的索引选中项上时，深色主题的选中会「塌下去」。改用 `background: var(--ink); color: var(--ground)` 反白条解决，同时也更符合 C 的反白语言。

**交付范围（写进规范 4.4，控制条上也标注了）**

`prototype.html` **只完整实现 A 布局**。其「配色令牌」开关只换色不换布局——已从「方向」改名为「配色令牌」，避免误读。
不在选定前做四套完整原型：其中三套会被丢掉。选定后按该布局重做原型（片库全部状态、空态、确认弹层跟着走）。

**技术备忘**

- 想在无头浏览器里单独看某个方向：python 复制 explorer + 注入 `.wrap > .dir:nth-child(k){display:none}` 生成只显示一个方向的副本
- `sips --cropOffset` 在偏移较大时会失效（返回整页缩略），小偏移可用

## v1.3 — 定稿：D 圆润亲和（磁贴网格）

用户选定「改成 D 圆润亲和的 UI 完整设计」。`prototype.html` 从「四方向令牌切换」**整体重写**为 D 的单一定稿。

**新原型的构成**

- 布局：2 列磁贴网格（`.tile` / `.tile.wide` 跨列），18 个磁贴、11 个宽磁贴、6 个网格
- 视觉：莓果 `#C03255` · 圆角 14–18px · 系统圆体 · 柔和多层投影 · **无描边分层**
- 三页全状态：播放/片库/通用 + 三种空态 + 队列五态 + 删除确认弹层 + 菜单栏面板 + 明暗
- 新增 `--divider` 令牌（= surface-2）：磁贴靠投影分层不需要描边，但磁贴**内部**仍需一条极淡分隔线

**踩到并修掉的两个真实陷阱（已写进规范 4.4）**

1. **`.tile` 自带 `flex-direction: column`，它不会被 `display` 覆盖，也不继承给子元素。**
   只写 `--d: flex` 会让 `.now`/`.empty`/`.qhead`/`.footbar`/`.about`/`.strip` 继续竖排，
   还被 `align-items: center` 横向居中——首屏「正在播放」的文字居中、倒计时环掉到下面就是这么来的。
   修法：这些磁贴显式写 `flex-direction: row`。
2. **`--d` 只对带 `data-when` 的元素生效。** `.eyebrow` 这种「可能带也可能不带状态切换」的元素
   必须**同时**写 `display: flex` 与 `--d: flex`；只写 `--d` 会退化成块级，把徽标挤到下一行（片库页的「3 个任务」就是这样）。

**审计脚本重写**

原来硬编码 `[data-dir="a".."d"]` 选择器，原型只剩 D 一套后必然找不到块。
改为按出现顺序自动抓取所有 `.scope` 块、每两块算一套，用 `--dirs` 传标签：
`contrast-audit.py prototype.html --dirs d` / `--dirs a,b,c,d`。
两文件共 **180 组配对全部达标**（原型 36 + 对照板 144）。

**观察到的取舍（未改动用户决定）**

`通用` 页在 D 的磁贴网格下只有两个磁贴（开机自启 + 关于），是全设计最轻的一页。已维持现状。

## 两个待定项已收敛（用户问「然后呢」后）

**① 两个 ViewModel 不合并 —— 用数据定论**

按项目自己的「抽象前先数重复」逐条对 `TranscodeViewModel`(107 行) 与 `FpsTranscodeViewModel`(93 行)，
**9 处语义差异**：Job 类型 / 源获取入口数 / 删源语义 / 帧率表 4 个读数 / isScanning /
canStart 归属 / 启动路径形状 / 依赖注入项 / 入队守卫。
项目门槛是 3+ 就不抽，9 处必然让钩子超过省下的重复。

**做法**：保留两个对象，只在视图层折叠成 `QueueRow`。代码里已有现成的缝——
`JobStatePresenting` 协议两份状态枚举都实现了，不需要新协议。
另建议给该协议加 `: Sendable`（两个枚举都是带 String 负载的值类型），省掉 `QueueRow` 的隔离注解。

**② 空态映射放 `SettingsPresentation` —— 我直接定了**

与既有 20 个纯映射函数同层、可单测。`isEmptyState(_:)` 不动，新增**平行**的
`emptyStateCopy(_:) -> EmptyStateCopy?`（title / reason / primaryAction）。
`emptyStateBody` 那句逐字硬需求三种变体共用。
