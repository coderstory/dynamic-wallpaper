## 第五轮：分批次提交

13 个提交（`3b3dd5a`..`870fd52`），已 push 到 `origin/dev`。

**拆分手法**（值得复用，脚本在 `/tmp/split_commits.py`）：同一插入点拆多段时**不要**做补丁外科手术 ——
`git apply --cached` 对同一锚点的多次插入有顺序问题。改成「按批次重建中间态」：
    S_i = 工作区终态 W  −  属于第 i+1..N 批的 hunk（删新增行 / 把改写还原成旧行）
逐批写回文件 → `git add` → `commit`。最后一批写回的就是 W，所以收尾 `git diff HEAD` 必为空。
按 `func` 边界切大块测试 hunk（纯新增 hunk 用偏移量切；父 hunk 标记 split 后不再单独处理）。
安全网：先 `git stash create` 拿一个快照 hash，拆完 `git diff <hash>` 只有未跟踪文件才算成功。

## 新增：C++ 线程安全单例日志器示例（与 Pic 主仓无关，独立目录）

目录 `cpp-singleton-logger/`（include/logger.hpp、src/logger.cpp、src/secondary.cpp、src/main.cpp、CMakeLists.txt）。
用途：交付「并发计数 + 线程安全 + 无数据竞争的 Meyers 单例日志器」，C++17，macOS clang 21 / CMake 4.4 实测通过。

- 设计：函数内 static 单例（不用双检锁）；`sink_mutex_` 只护输出动作，计数全走 `std::atomic`（relaxed）；
  时间戳用 `localtime_r`/`localtime_s`（`std::localtime` 是共享静态缓冲区 → 数据竞争）；线程标记用
  `thread_local` 惰性分配序号；格式化在锁外完成，临界区只剩一次 `write()`。
- 实证：8 线程 × 20000 条 → 计数逐项精确（logged=160009 / filtered=400 / INFO=160000 / ERROR=8 / WARN=1），
  `-fsanitize=thread` 下 0 警告（`otool -L` 确认 libclang_rt.tsan 已注入），ASan 亦干净，ctest 1/1 通过。
- **踩坑（值得记住）**：`add_compile_options` / `add_link_options` 只对「其后创建」的 target 生效。
  写在 `add_library` 之后会静默失效 —— 第一次 TSan「通过」其实是没插桩的假通过。
  sanitizer/warning 开关一律用 `target_compile_options` + `target_link_options`（本工程用 INTERFACE 库 `pic_log_flags` 下发）。
